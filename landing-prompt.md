# Промт для Claude Code — Лендінг Majstr

> Скопіюй цей промт у Claude Code. HTML-референс дизайну — у файлі
> majstr-landing.html (прикладений поруч), дай його Claude Code як зразок
> вигляду й текстів.

---

## ПРОМТ

```
Створи публічну лендінг-сторінку (головну) для незалогінених користувачів
у PWA Majstr (React + TS + Vite + Tailwind + React Router).

КОНТЕКСТ ПРОДУКТУ:
Majstr — інструмент для майстрів-будівельників (електрики, плиточники,
сантехніки, маляри) для складання кошторисів клієнтам. Ключове: створив
кошторис → надіслав клієнту посиланням → клієнт переглянув і підписав онлайн.
Позиціонування: "професійний кошторис без зайвого" — простий інструмент
для соло-майстра, НЕ складний комбайн для проєктних бюро.

ДИЗАЙН-РЕФЕРЕНС:
Прикладаю готовий HTML-макет (majstr-landing.html) з усім дизайном, текстами,
кольорами і структурою. Відтвори ЦЕЙ вигляд і ці тексти в React-компонентах.
Естетика: технічне креслення / робоча специфікація — графіт (#16202b) +
теплий папір (#f5f3ee) + будівельний жовтий акцент (#f0a818), моноширинний
шрифт у деталях (ціни, мітки). НЕ глянцевий стартап-вигляд.

ЩО ЗРОБИТИ:

1. РОУТИНГ (головне):
   - Маршрут "/" для НЕзалогінених → показує Лендінг
   - Маршрут "/" для ЗАЛОГІНЕНИХ → редірект на дашборд (як зараз)
   - Кнопки "Почати безкоштовно" → /register
   - Кнопка "Увійти" (у nav) → /login
   - Не зламати наявний роутинг застосунку та портал клієнта

2. КОМПОНЕНТ ЛЕНДІНГУ:
   - Розбий на логічні React-компоненти (Hero, TradesStrip, ProblemSolution,
     Features, HowItWorks, FinalCTA, Footer) — або один Landing з секціями,
     як зручніше у вашій структурі
   - Відтвори структуру з макета: nav → hero (заголовок + мокап телефону
     з прикладом кошторису) → смуга трейдів → проблема/рішення →
     4 переваги → 3 кроки → фінальний CTA → футер
   - Тексти ВЗЯТИ з макета (українською, вони продумані)
   - Мокап телефону в hero — відтвори (приклад кошторису електрика з підписом)

3. СТИЛІ:
   - Використати Tailwind (проєкт на ньому). Кольори з макета додати в
     tailwind config як кастомні (ink, paper, amber тощо) або через
     CSS-змінні — як прийнято у вашому проєкті
   - Моноширинний шрифт для цін/міток (JetBrains Mono або системний mono)
   - ПОВНІСТЮ адаптивно: мобільний-перший (аудиторія на телефонах!).
     Перевір що на ~375px все читабельно й не ламається
   - Hover-стани кнопок/карток, плавні переходи

4. SEO + МЕТА (важливо для індексації):
   - <title>Majstr — професійний кошторис для майстра, без зайвого</title>
   - meta description (з макета)
   - og:title / og:description / og:type (з макета)
   - lang="uk"
   - семантичні теги (header, section, footer, h1/h2/h3 ієрархія)
   - Якщо у вас SPA без SSR — переконатись що базові мета-теги в index.html
     або через react-helmet/аналог, щоб Google бачив контент.
     Розглянь: чи варто prerender головної для SEO (vite-plugin що генерує
     статичний HTML головної) — якщо просто, додай; якщо складно, лиши на потім
     і познач у документації як TODO для SEO

5. КОНТАКТИ:
   - У футері й CTA — реальні: support@majstr.pro, +380978938990
   - Брати з env (VITE_SUPPORT_EMAIL, VITE_SUPPORT_PHONE) якщо вони вже є,
     інакше захардкодити з коментарем

ВАЖЛИВО:
- Це ПУБЛІЧНА сторінка — жодних запитів до API що вимагають авторизації
  (лендінг має відкриватись миттєво без бекенду)
- Не чіпати логіку застосунку, порталу клієнта, реєстрації/логіну —
  тільки додати лендінг як публічну головну + правильний редірект
- Зберегти стиль кодової бази, нічого не видаляти зайвого

ОНОВИ ДОКУМЕНТАЦІЮ:
- docs/SPEC.md — додати секцію про лендінг (публічна головна, маршрутизація
  незалогінений→лендінг/залогінений→дашборд, SEO-теги)
- docs/PROMPTS.md — цей крок
- якщо SSR/prerender лишив на потім — записати в open-questions.md як
  TODO для SEO-індексації головної

ПІСЛЯ:
- Покажи що додав (компоненти, зміни роутингу, мета-теги)
- Поясни як підняти локально щоб подивитись (npm run dev → який URL)
- Підтверди: незалогінений на "/" бачить лендінг, залогінений → дашборд,
  кнопки ведуть на /register і /login, мобільний вигляд не ламається
```

## 📎 ЯК ПЕРЕДАТИ РЕФЕРЕНС

```
1. Поклади majstr-landing.html у корінь PWA-репо (тимчасово) або відкрий
   поруч — щоб Claude Code бачив зразок вигляду й текстів
2. Скажи Claude Code: "дизайн і тексти бери з majstr-landing.html"
3. Після інтеграції можеш видалити majstr-landing.html з репо (він лише зразок)
```

## 🎬 ПІСЛЯ ТОГО ЯК ПІДНІМЕШ ЛОКАЛЬНО

```
- Глянь на десктопі І на телефоні (звузь вікно або DevTools mobile view)
- Обдумай: меседж, тексти, вигляд, чого бракує
- НЕ поспішай пушити в прод — спочатку відчуй чи воно "твоє"
- Як надумаєш правки — повертайся, покрутимо текст/блоки,
  потім фінальний варіант у прод
```

## ⚠️ НА ЩО ЗВЕРНУТИ УВАГУ ЛОКАЛЬНО

```
1. Редірект: залогінений на "/" має йти на дашборд (не бачити лендінг)
2. Незалогінений на "/" → лендінг (не одразу /login як було)
3. Кнопки реально ведуть на /register і /login
4. Мобільний вигляд — головне (аудиторія на телефонах)
5. Портал клієнта (api.majstr.pro/portal) — НЕ зачеплений
6. Швидкість — лендінг має вантажитись миттєво (без виклику API)
```
