# Промти для Claude Code — Лендінг + Портал клієнта (єдиний дизайн)

> Два окремі промти (різні репо, різні технології):
>   1. ЛЕНДІНГ → majstr-pwa (React)
>   2. ПОРТАЛ КЛІЄНТА → majstr-backend (static/portal/index.html)
> Обидва в єдиному дизайні. Дизайн-референс: majstr-landing-final2.html
> (світлий теплий коричневий + яскравий помаранчевий як у Majstr апці).

ДИЗАЙН-СИСТЕМА (спільна для обох — щоб бренд був цілісний)
═══════════════════════════════════════════════════════════════════

Кольори (CSS-змінні):
  --ink:       #3a2519   (тепла кора дуба — основний темний: текст, шапки, кнопки)
  --ink-2:     #4a3122   (hover темного)
  --paper:     #f7f1e7   (теплий папір — фон сторінки)
  --paper-2:   #ede2d1   (трохи темніший папір)
  --line:      #d9ccb5   (тепла лінія/межі)
  --amber:     #f5821f   (яскравий помаранчевий — акцент, як у Majstr апці:
                          кнопки дії, підпис, важливі мітки, підкреслення)
  --amber-deep:#e06c00   (hover/насиченіший акцент)
  --muted:     #705c47   (приглушений теплий — другорядний текст)
  --white:     #ffffff

Типографіка:
  - Основний шрифт: Inter (або системний sans-serif)
  - Моноширинний (JetBrains Mono / системний mono) для: цін, телефонів,
    технічних міток (напр. "ОБ'ЄКТ", суми, "//"-роздільники)
  - Заголовки — жирні (800), щільні (letter-spacing трохи мінусовий)

Характер: тепло, ремісничо, "професійно без зайвого". Чисто, без декору
заради декору. Естетика технічного креслення/специфікації, але тепла.

═══════════════════════════════════════════════════════════════════
ПРОМТ 1 — ЛЕНДІНГ (репо majstr-pwa, React)
═══════════════════════════════════════════════════════════════════

```
Створи публічну лендінг-сторінку (головну) для НЕзалогінених у PWA Majstr
(React + TS + Vite + Tailwind + React Router).

Дизайн і тексти — з прикладеного majstr-landing-final2.html (відтвори вигляд,
кольори, структуру, тексти 1-в-1). Поклади цей HTML у репо як зразок або
відкрий поруч.

КОНТЕКСТ ПРОДУКТУ: Majstr — інструмент для майстрів-будівельників (електрики,
плиточники, сантехніки, маляри) для кошторисів клієнтам. Позиціонування:
"професійний кошторис без зайвого" — простий інструмент для соло-майстра.

ЩО ЗРОБИТИ:

1. РОУТИНГ (головне):
   - "/" для НЕзалогіненого → Лендінг
   - "/" для ЗАЛОГІНЕНОГО → редірект на дашборд (як зараз)
   - кнопки "Почати безкоштовно" → /register; "Увійти" → /login
   - НЕ зламати наявний роутинг застосунку і портал клієнта

2. СТРУКТУРА (з референсу): nav → hero (заголовок "Професійний кошторис
   без зайвого" з помаранчевим підкресленням + мокап телефону з прикладом
   кошторису електрика + кнопки + нотатка "безкоштовно без картки") →
   смуга трейдів (// Електрики // Плиточники // Сантехніки // Маляри //
   Будь-який ремонт) → проблема/рішення (як зазвичай vs з Majstr) →
   4 переваги → 3 кроки (склади→надішли→підпис) → фінальний CTA → футер
   з реальними контактами (support@majstr.pro, +380978938990).

3. СТИЛІ:
   - Tailwind. Кольори з дизайн-системи вище — у tailwind config (кастомні
     ink/paper/amber...) або CSS-змінні, як прийнято у проєкті.
   - Моно-шрифт для цін/міток. Помаранчевий #f5821f — акцент (кнопки, підпис,
     підкреслення заголовка), яскравий як у застосунку.
   - ПОВНІСТЮ адаптивно, МОБІЛЬНИЙ-ПЕРШИЙ (аудиторія на телефонах!).
     Перевір ~375px — нічого не ламається.
   - Hover-стани, плавні переходи.

4. SEO/МЕТА (важливо для індексації):
   - <title>Majstr — професійний кошторис для майстра, без зайвого</title>
   - meta description, og:title/description/type (з референсу), lang="uk"
   - семантика (header/section/footer, h1/h2/h3)
   - SPA без SSR → базові мета в index.html або react-helmet, щоб Google бачив.
     Якщо просто додати prerender головної (vite-plugin) — додай; якщо
     складно — TODO в open-questions для SEO.

5. Це ПУБЛІЧНА сторінка — БЕЗ запитів до API (вантажиться миттєво без бекенду).
   Контакти з env (VITE_SUPPORT_EMAIL/PHONE) якщо є, інакше з референсу.

НЕ чіпати: логіку застосунку, портал, реєстрацію/логін — лише додати лендінг
+ редірект.

ОНОВИ ДОКУМЕНТАЦІЮ: docs/SPEC.md (публічний лендінг, маршрутизація, SEO),
docs/PROMPTS.md.

Покажи що додав; як підняти локально (npm run dev → URL); підтверди:
незалогінений на "/" бачить лендінг, залогінений → дашборд, кнопки ведуть
на /register і /login, мобільний не ламається.
```

═══════════════════════════════════════════════════════════════════
ПРОМТ 2 — ПОРТАЛ КЛІЄНТА (репо majstr-backend, статичний HTML)
═══════════════════════════════════════════════════════════════════

```
Перероби ДИЗАЙН порталу клієнта Majstr під новий бренд-стиль, ЗБЕРІГШИ
ВЕСЬ функціонал. Це static/portal/index.html у backend-репо (віддається
з origin бекенду, api.majstr.pro/portal/index.html?t=<token>).

🔴 НАЙВАЖЛИВІШЕ — ЗБЕРЕГТИ ВСЕ ЩО ПРАЦЮЄ, міняти ТІЛЬКИ вигляд:
- НЕ чіпати логіку: завантаження кошторису по токену (?t=), будь-який JS,
  запити до API, обробку відповідей
- НЕ чіпати кнопки/дії: підпис кошторису, перегляд позицій, усі інтерактивні
  елементи — лишаються РОВНО ТАКІ Ж за поведінкою
- НЕ чіпати дані що показуються (майстер, контакти, об'єкт, роботи, матеріали,
  суми, статуси, логотип з logoUrl)
- НЕ ламати стани: завантаження, помилка (невалідний токен), підписано тощо
- ЗМІНИТИ ТІЛЬКИ: кольори, шрифти, відступи, вигляд карток/кнопок/шапки —
  презентаційний шар (CSS + розмітка-обгортка за потреби)

ДИЗАЙН — той самий що лендінг (єдиний бренд). Застосуй дизайн-систему:
  - фон сторінки: теплий папір #f7f1e7
  - картки: білі, м'які кути, тонка тепла межа (#d9ccb5), легка тінь
  - шапка з даними майстра: темний фон кора дуба #3a2519, світлий текст,
    телефон моноширинним
  - мітки секцій ("ОБ'ЄКТ", "РОБОТИ", "МАТЕРІАЛИ") — дрібні, моно,
    помаранчеві #f5821f, letter-spacing
  - суми/ціни — моноширинний шрифт
  - рядок "РАЗОМ" — виділений, жирний, з верхньою лінією
  - кнопка/дія "Підписати кошторис" — яскравий помаранчевий #f5821f фон,
    темний текст, помітна (головна дія порталу!)
  - логотип майстра (logoUrl) — лишити де є, акуратно в шапці
  - загальний характер: чисто, тепло, професійно, мобільний-перший
    (клієнт відкриває з телефона!)

Орієнтуйся візуально на мокап телефону в majstr-landing-final2.html (там
саме картка кошторису в цьому стилі) — портал має виглядати як "великий
брат" того мокапа.

⚠️ ПЕРЕВІР ПІСЛЯ ЗМІН (нічого не зламано):
- портал відкривається по реальному токену → кошторис показується
- усі дані на місці (майстер, об'єкт, роботи, суми, логотип)
- підпис кошторису ПРАЦЮЄ (головна дія!)
- стани помилки/завантаження/підписано — коректні
- мобільний вигляд (клієнт на телефоні) — не ламається
- кирилиця нормальна

НЕ чіпати: backend-логіку, PublicEstimateService, ендпоінти, генерацію
токенів — ТІЛЬКИ static/portal/index.html (вигляд).

ОНОВИ ДОКУМЕНТАЦІЮ: docs/SPEC.md (портал клієнта — редизайн під бренд-стиль,
функціонал незмінний), docs/PROMPTS.md.

Покажи до/після (скриншот або опис вигляду); підтверди що ВЕСЬ функціонал
(підпис, дані, стани) збережено, змінено лише дизайн.
```

═══════════════════════════════════════════════════════════════════
ПОРЯДОК І ПОРАДИ
═══════════════════════════════════════════════════════════════════

1. Спочатку ЛЕНДІНГ (Промт 1) → підняти локально → переконатись що добре →
   за потреби покрутити → і тільки потім у прод (push).
2. Потім ПОРТАЛ (Промт 2) → це backend-репо → локально перевірити що підпис
   та дані працюють → потім прод.
3. Дизайн-референс majstr-landing-final2.html дай Claude Code в ОБИДВА рази
   (це джерело вигляду й кольорів).

⚠️ Портал — обережно: це те що бачить КЛІЄНТ майстра. Зламати підпис/дані =
зламати ключовий сценарій. Тому наголос "зберегти весь функціонал, тільки
дизайн" — критичний. Після редизайну ОБОВ'ЯЗКОВО перевір реальний підпис
кошторису через портал.

⚠️ Після обох змін — портал і лендінг в одній гамі з застосунком = цілісний
бренд. Це підсилює "найкращий портал клієнта" (твоя перевага з аналізу).
